work. The implementation and this record are maintained together in the

## What changed

| Area | Implemented behavior | Main files |
|---|---|---|
| Historical TimesFM failures | Model-load or inference failures raise and abort the backtest, including mixed-indicator strategies. The UI shows the error without success metrics or a downloadable success archive. | [forecast indicator](../indicators/forecast.py), regression tests |
| Interactive forecast failures | Retains the original error and returns no forecast. Reading the prepared frame does not retry inference for every bar. A later batch failure clears earlier partial predictions. | [forecast indicator](../indicators/forecast.py) |
| Completed simulator bars | Removes today's and future daily bars before preparing signals or constructing the replay, using the provider's timezone or UTC for naive dates. The saved simulation history and later strategy changes use the same filtered frame. Empty completed history produces an error. | [Simulator page](../ui/page_simulator.py) |
| Historical input memory | Slices to effective context before float32 conversion; constructs origins lazily and prepares at most one configured chunk at a time. Input arrays are released between batches. Forecast timing and origin availability are preserved. | [forecast indicator](../indicators/forecast.py), [benchmark](../ml/benchmark.py) |
| Experimental TimesFM 3.0 | Adds an explicit `backend` setting with automatic matching default checkpoint IDs; 2.5 remains the default. Adds the lazy 3.0 adapter with device and output validation. | [runtime](../ml/timesfm_runtime.py), [3.0 adapter](../ml/timesfm3_backend.py) |
| Model controls | Adds the **TimesFM Model** dashboard selector and `--backend 2.5\|3.0` to runtime-check and single-model benchmark CLIs. Model selection participates in the UI settings signature and recorded configuration identity. | [UI controls](../ui/components.py), [runtime check](../scripts/timesfm_check.py), [benchmark CLI](../scripts/benchmark_timesfm.py) |
| Model comparison | Adds suite `mode: "models"`: two separately bounded workers per asset/horizon, one frozen input snapshot, forecast and backtest results, fixed baselines, preserved failures, and a self-contained HTML comparison. | [suite](../research/suite.py), [comparison artifacts/report](../research/timesfm_comparison.py), [suite CLI](../scripts/benchmark_suite.py) |
| Linux RAM reporting | Uses `MemAvailable` from `/proc/meminfo`, including reclaimable cache, instead of rejecting healthy machines based only on unused pages. Runtime preflight and hardware profiles now share this check; other platforms retain the free-page fallback. | [profiles](../ml/timesfm_profiles.py), [runtime](../ml/timesfm_runtime.py) |
| Installation and documentation | Adds a separate `timesfm==3.0.2` requirements file; ignores `.venv-timesfm3/`; documents experimental setup, limits, comparison protocols and archive types. | [experimental requirements](../requirements-timesfm3.txt), [.gitignore](../.gitignore), [TimesFM guide](TIMESFM.md), [research workflow](RESEARCH_WORKFLOW.md), [operation guide](AGENT_OPERATIONS.md), [README](../README.md) |

No strategy weights, thresholds, fee defaults or fill-accounting rules were
changed. No broker interface, ongoing job or public deployment was added.

### Memory regression result

For 2,000 bars, horizon one, effective context 64 and chunk size 32:

- Previously, full-prefix input arrays totaled **8,002,016 bytes**.
- Capped input arrays total **501,952 bytes** over the whole operation.
- Only **8,192 bytes (8 KiB)** of prepared input arrays are held per batch.

This measures input arrays, not total process or GPU memory. The result frame
still scales with history length. Tests verify exact causal slices, release of
previous arrays, unchanged forecasts with an injected context-sensitive model,
and failures after a successful earlier batch.

### TimesFM 3.0 boundaries

The experimental backend targets the official `timesfm==3.0.2` package. That
package includes both the 2.5 and 3.0 APIs. The new adapter uses
`TimesFM3Evaluator` and converts its median and nine quantiles to the existing
runtime format. Counts, shapes, finite values, quantile order, and loaded
parameter/buffer devices are checked. Historical origins remain independent
one-dimensional examples, not channels of a multivariate example.

Both integrations currently use **closing prices only**. Native 3.0 covariates
and multivariate forecasting are not implemented. The 3.0 adapter uses eager
inference and records `torch_compile=false`; its context limit is 15,360 bars.
It requests symmetric averaging, positivity handling, sorted quantiles, no
external z-normalization, and no edge padding. These adapter choices are fixed,
not selected using the AAPL outcome.

The [3.0 downloaded-weight license](https://huggingface.co/google/timesfm-3.0-pytorch/blob/main/LICENSE)
restricts use to non-commercial, non-production purposes, including commercial
use of outputs. The 2.5 weights remain Apache-2.0. Quantile-derived scores are
uncalibrated for profitable execution.

## Set up an environment that survives temporary-directory cleanup

The code and reports are in the project directory. The interpreter and weights
used for the live run are under `/tmp` and may be removed by host cleanup.
The base/global Python environment was not upgraded. Create a fresh persistent
environment rather than relying on those temporary paths:

```bash
python3.11 -m venv .venv-timesfm3
.venv-timesfm3/bin/python -m pip install --require-hashes -r requirements-lock.txt
```

On the GPU setup tested here, PyTorch 2.8.0 with CUDA 12.8 was used:

```bash
.venv-timesfm3/bin/python -m pip install 'torch==2.8.0' \
  --index-url https://download.pytorch.org/whl/cu128
.venv-timesfm3/bin/python -m pip install -r requirements-timesfm3.txt
.venv-timesfm3/bin/python -m pip check
```

Use the appropriate PyTorch build for another machine. For CPU-only testing,
the alternative PyTorch index is `https://download.pytorch.org/whl/cpu` and
the runtime device should be `cpu`. Do not combine `requirements-timesfm.txt`
with `requirements-timesfm3.txt`: they deliberately pin different versions of
the same package. Keep the existing 2.5 environment if you need it.

Inspect dependencies and hardware without downloading or loading weights:

```bash
.venv-timesfm3/bin/python -m scripts.timesfm_check --backend 2.5 --device cuda
.venv-timesfm3/bin/python -m scripts.timesfm_check --backend 3.0 --device cuda
```

Explicit smoke tests will load each model and download it into the normal
persistent Hugging Face cache if needed. Together, the two checkpoint files
used in this run are about 2.25 GB; PyTorch/CUDA dependencies require additional
space. With `HF_HUB_CACHE` unset, these do not use the temporary cache above:

```bash
.venv-timesfm3/bin/python -m scripts.timesfm_check \
  --backend 2.5 --device cuda --profile fast --smoke --no-torch-compile
.venv-timesfm3/bin/python -m scripts.timesfm_check \
  --backend 3.0 --device cuda --profile fast --smoke
.venv-timesfm3/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

The portable installation commands are documented recipes, not environments
created by this session. The actual tested environment is recorded below.

### Run the saved comparison again

With both checkpoints cached in the selected model environment:

```bash
.venv-timesfm3/bin/python -m scripts.benchmark_suite \
  research_runs/20261020-aapl-timesfm-inputs-001/protocol.json \
  --output-dir research_runs/aapl-timesfm-comparison-002
```

Use a new output directory every time. The suite loads cached weights only,
snapshots the saved input, starts workers sequentially, and keeps failure and
timeout records. To use other data or dates, create a new input/protocol using
the [TimesFM guide's example](TIMESFM.md#experimental-timesfm-30-comparison).
Settings and boundaries must be fixed before viewing outcomes.

A rerun under different dependencies, checkpoints or source is a new run, not
an exact reproduction. `model_comparison` archives can be inspected and verified;
they are not accepted by the backtest-only replay function.

### Observed results

| Metric | TimesFM 2.5 | TimesFM 3.0 |
|---|---:|---:|
| Median return forecast MAE, percentage points | 3.4084 | 3.2101 |
| Direction accuracy | 36% | 44% |
| Coverage of nominal 80% interval | 80% | 76% |
| Backtest return after selected fill costs | -16.08% | -6.40% |
| Maximum drawdown | 16.08% | 10.18% |
| Trades | 3 | 7 |
| Worker elapsed seconds, including loading and evaluations | 16.52 | 26.11 |

Predicting no price change had **3.0740 percentage points MAE**, lower than
either model. Over the matching requested backtest window, buy-and-hold returned
**+26.96%**, SMA **+7.01%**, and cash **0%**, under their recorded fee policies.

TimesFM 3.0 performed better than 2.5 on several measures in this sample, but
neither model beat those simple baselines. Twenty-five forecasts and three or
seven trades do not establish statistical significance or a trading edge.
Nominal interval coverage is descriptive, not calibration proof. This uses
current pretrained weights and a current adjusted-price snapshot; it does not
prove historical model availability or absence of pretraining overlap.
Backtests retain the existing margin/borrow-cost omissions.
